# JLPT Content Authoring — 직접 작성 콘텐츠 규칙

이 앱의 문법 설명, 문제, 청해 대본은 직접 쓴다. 잘 쓴 콘텐츠는 사용자를 합격시키고, 베낀 콘텐츠는 앱을 내리게 만들며, 정답이 둘인 문제는 학습자를 헷갈리게 한다. 아래 규칙은 이 세 가지에 맞춰져 있다.

## 1. 독창성

- 기출 문제, 공식 문제집, 시판 교재, 유료 강의의 문항·지문·예문·해설을 옮기지 않는다. 단어나 숫자만 바꾼 변형, 구조를 그대로 따른 번안도 포함한다.
- 문장이 "어디서 본 것 같으면" 버리고 새로 쓴다. 기억에서 꺼낸 예문은 출처를 모르는 예문이다.
- 외부 문장은 `content-licensing`에서 `확정`된 자료(예: Tatoeba)만, 원문 ID를 `sources`에 적어서 쓴다.
- 짧은 관용 표현(あいさつ, 정형구)처럼 누구나 같은 형태로 쓰는 문장은 복제가 아니다. 다만 그것을 둘러싼 문항·맥락은 새로 쓴다.

## 2. 급수 적합성

- 해당 급수와 그 아래 급수의 어휘·문법만 쓴다. 급수는 `docs/content/sources.md`에서 확정된 목록 기준이며 공식이 아니다.
- 급수를 넘는 단어가 꼭 필요하면 후리가나와 한국어 뜻을 단다. 문항의 정답 판단에 필요한 단어는 급수 안에서 고른다.
- 한자 표기는 급수에 맞춘다. 낮은 급수에서는 히라가나 표기를 우선한다.

## 3. 파일 형식(`content/authored/`)

구체 스키마는 `docs/spec/architecture.md`가 정한다. 모든 항목이 공통으로 갖는 필드:

| 필드 | 뜻 |
|------|-----|
| `id` | 안정 ID(예: `gr-n4-0012`, `q-n3-vocab-0040`, `ls-n5-0003`). 한 번 배포하면 바꾸지 않는다 |
| `level` | `N5`~`N1` |
| `status` | `draft` / `reviewed` / `retired` |
| `needsReview` | 정확성이 확실하지 않을 때 `true` |
| `sources` | 외부 자료를 쓴 경우 `[{ "source": "<매니페스트 id>", "ref": "<원문 ID>" }]`, 없으면 `[]` |

- 큰 수정은 새 ID로 추가하고 옛 항목을 `retired`로 둔다. 사용자의 학습 기록이 옛 ID를 가리키고 있다.
- 파일을 고친 뒤 `verify.sh`를 실행해 파이프라인 형식 검사를 통과시킨다.

## 4. 문법 항목

- 한국어 설명은 한국어 화자의 관점으로 쓴다: 대응하는 한국어 표현, 한국어와 다른 점, 자주 하는 실수.
- 접속 형태(품사·활용형)를 표로 적는다.
- 예문 3개 이상, 각 예문에 한국어 번역. 예문은 서로 다른 장면·접속 형태를 보인다.
- 비슷한 문법(예: 〜ために / 〜ように)이 있으면 차이를 예문 쌍으로 보인다.
- 문법 설명이 학설·사전마다 갈리면 단정하지 말고 일반적인 쓰임을 적고 `needsReview`로 표시한다.

## 5. 문제

### 유형

JLPT 영역 구성을 참고한 유형 이름(앱 내부 분류):

| 영역 | 유형 |
|------|------|
| 문자·어휘 | 한자 읽기, 표기, 단어 형성, 문맥 규정, 유의 표현, 용법 |
| 문법 | 문법 형식 판단, 문장 배열, 글의 문법 |
| 독해 | 단문, 중문, 장문, 통합 이해, 주장 이해, 정보 검색 |
| 청해 | 과제 이해, 포인트 이해, 개요 이해, 발화 표현, 즉시 응답, 통합 이해 |

급수마다 실제로 출제되는 유형이 다르므로 급수별 구성은 공개된 시험 안내(주최 측 공식 안내 페이지)의 형식 설명을 확인해 `architecture.md`에 적는다. 문항 수·시간·배점은 "실제 시험과 다를 수 있음"을 앱에 표시한다.

### 출제 규칙

- 정답은 하나다. 각 오답이 왜 틀렸는지 한국어로 설명할 수 없으면 문항을 고친다.
- 오답은 정답과 같은 품사·형태로 만들고, 학습자가 실제로 헷갈리는 지점(비슷한 한자, 비슷한 문법)을 겨냥한다. 말이 안 되는 오답은 변별력이 없다.
- "모두 맞음", "정답 없음" 선택지를 쓰지 않는다.
- 정답 위치가 한쪽에 몰리지 않게 한다(파이프라인 검사로 분포 확인).
- 문항마다 `targets`(관련 어휘·문법 ID)를 적어 틀린 문항에서 복습으로 이어지게 한다.
- 해설: 정답 근거, 오답별 이유, 관련 문법·어휘 링크.

### 모의고사

- 급수별 영역 구성을 따르되 문항은 이 스킬로 새로 쓴 것만 쓴다.
- 점수는 원점수(영역별 정답 수·비율)로 보여 준다. 공식 척도 점수 환산 방식은 공개되지 않았으므로 합격 여부를 예측하거나 척도 점수를 흉내 내지 않는다.

## 6. 청해 대본

- 대본, 화자 표시(예: `M`, `F`, 내레이션), 질문, 선택지, 정답, 한국어 해설.
- 음성은 기기 TTS(ja-JP)가 읽는다. 동형이음어(예: 今日, 上手), 숫자·조수사, 고유명사처럼 TTS가 잘못 읽기 쉬운 곳은 `ttsText`에 읽기를 가나로 바꾼 문장을 함께 둔다.
- 화자가 둘 이상이면 TTS 음성·높이 차이로 구분할 수 있게 화자 정보를 남긴다. 기기에 음성이 하나뿐일 때도 이해할 수 있게 대본에 화자를 드러낸다.
- 실제 시험 음원을 받아 적은 대본, 시험 상황 설정을 그대로 옮긴 대본을 쓰지 않는다.

## 7. 한국어 뜻 검수

- 파이프라인이 만든 뜻(`content-licensing` 4절 방식 A)을 묶음 단위로 검수한다. 검수 범위(전수 또는 표본 크기, 검수자 종류)는 사용자가 `docs/content/decisions.md` D-03에서 정한다. 정하기 전에는 마일스톤에 적힌 범위를 따르고, 에이전트 검수를 사람 검수로 기록하지 않는다.
- 확인할 것: 의미가 맞는가, 품사·뉘앙스가 맞는가, 여러 뜻 중 학습에 필요한 뜻이 앞에 오는가, 한국어로 자연스러운가.
- 결과는 행의 검수 상태 열과 `_workspace/03_jlpt-content-author_{마일스톤ID}_review.md`(검수한 ID, 고친 내용, 날짜)에 남긴다.

## 8. 콘텐츠 리뷰 기준(리뷰어용)

지적의 심각도:

- `high`: 정답이 둘 이상이거나 없음, 일본어 문법·표기 오류, 한국어 설명이 틀림, 기출·교재 복제 의심(근거: 일치하는 문장이나 출처), 출처 기록 없는 외부 문장, 급수를 크게 넘는 어휘로 문항 성립이 흔들림
- `medium`: 부자연스러운 일본어·한국어, 오답이 너무 쉬워 변별력이 없음, 해설 누락, TTS 읽기 힌트가 필요한데 없음
- `low`: 문체 통일, 예문 다양성

복제 의심은 "어디서 본 것 같다"만으로 `high`를 주지 않는다. 일치하는 원문을 찾았거나(웹 검색 결과), 시험·교재의 고유한 설정·인물·수치가 그대로 보일 때 근거와 함께 지적한다.
