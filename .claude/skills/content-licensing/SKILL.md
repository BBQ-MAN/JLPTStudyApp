# Content Licensing — 출처와 라이선스 규칙

학습 앱의 가치는 콘텐츠에 있고, 콘텐츠의 위험도 거기에 있다. 출처를 모르는 문장 하나가 앱 전체 배포를 막을 수 있다. 그래서 모든 콘텐츠는 원 출처에서 확인된 자료에서만 오고, 그 확인 근거가 문서에 남는다. 이 스킬은 근거 기록 규칙이지 법률 자문이 아니다. 판단이 갈리는 지점은 사용자 승인 항목으로 올린다.

## 1. 금지 목록

| 쓰지 않는 것 | 이유 |
|--------------|------|
| JLPT 기출 문제·공식 문제집의 문항·지문·음성 | 주최 측 저작물이다 |
| 시판 교재·문제집·유료 강의의 문장, 문항, 해설 | 저작물이다. 단어만 바꾼 변형도 포함 |
| 출처·라이선스가 불분명한 웹 단어장, 예문 모음, 앱 데이터 | 원 저작자와 조건을 확인할 수 없다 |
| 녹음 음성(시험·교재 음원, 웹 발음 사이트, Tatoeba 음성 포함) | 음성마다 별도 권리가 있다. 청해 음성 방식(기기 TTS / 사전 생성 음성)은 `docs/content/decisions.md` D-04에서 사용자가 정한다. 정하기 전 기본은 기기 TTS(ja-JP)이며 음성 파일을 번들하지 않는다. 라이선스가 확인된 음성만 예외로 하되 사용자 승인을 받는다 |
| 2차 글(블로그, 포럼)만을 근거로 한 라이선스 판단 | 원 출처 문장이 아니다 |

- JLPT 공식 어휘·문법 목록은 2010년 개정 이후 공개되지 않았다. 앱의 급수 표시는 커뮤니티 추정이며, 앱과 문서에 "공식 아님"을 밝힌다.
- 문제 유형의 구성(예: "한자 읽기", "문맥 규정")은 시험 형식에 대한 사실이므로 참고할 수 있지만, 문항 문장은 직접 쓴다(`jlpt-content-authoring`).

## 2. 후보 자료와 확인 항목

아래는 **후보**다. 라이선스 칸은 사용자가 알려 준 값이며 아직 확인되지 않았다. 설계 단계에서 원 출처를 열어 확인하고 `sources.md`에 근거와 함께 적는다.

| 후보 | 알려진 라이선스(미확인) | 원 출처에서 반드시 확인할 것 |
|------|------------------------|------------------------------|
| JMdict (EDRDG) | CC BY-SA 4.0 | EDRDG 라이선스 페이지의 저작자 표시 문구·링크 요구, 판(날짜)과 내려받기 URL, 앱 배포 시 조건. 뜻은 주로 영어이며 한국어 뜻은 거의 없다. JLPT 급수 정보는 없다 |
| KANJIDIC2 (EDRDG) | CC BY-SA 4.0 | 위와 같음. 한국어 음(`korean_h`, `korean_r` 읽기) 필드의 존재와 내용. `jlpt` 필드는 2010년 이전 4단계 체계라 N1~N5와 1:1로 맞지 않는다 |
| KanjiVG | CC BY-SA 3.0 | 저작자 표시 문구, 변형(필순 재가공) 시 조건, 판과 내려받기 URL |
| Tatoeba 예문 | CC BY 2.0 FR | 문장별 라이선스(일부 CC0 등 다를 수 있음), 저작자 표시 방식(문장 ID·기여자), 내려받기 파일 구성, 일본어–한국어 대응 문장 수. 음성은 별도 라이선스라 쓰지 않는다 |
| 커뮤니티 JLPT 급수 목록 | 미확인 | 목록 작성자, 라이선스 문구 원문, 원 목록과 파생 목록(GitHub 등)의 관계, 파생 목록의 라이선스가 원 목록과 맞는지. 확인할 수 없으면 쓰지 않는다 |
| 일본어 글꼴(번들할 경우, 예: Noto Sans JP) | 미확인 | 라이선스(예: SIL OFL)와 앱 번들 조건. 기기 글꼴만 쓰면 기록 불필요 |

새 후보를 더할 때도 같은 열(자료, 판, 라이선스, 쓰는 부분, 쓰지 않는 부분, 의무)을 채운다.

## 3. 기록 형식

### `docs/content/sources.md`

```markdown
# 콘텐츠 출처와 라이선스
마지막 갱신: YYYY-MM-DD · 이 문서는 근거 기록이며 법률 자문이 아니다.

## 0. 상태 요약
| ID | 자료 | 판·날짜 | 라이선스 | 상태(확정/미확정/제외) | 근거 URL | 확인일 |

## S-01 JMdict
| ID | 항목 | 내용 | 근거(URL, 인용 문장) | 상태 |
| S-01.license | 라이선스 | ... |
| S-01.attribution | 저작자 표시 문구 | ... |
| S-01.sharealike | 동일조건변경허락 의무와 앱에 미치는 영향 | ... |
| S-01.used | 쓰는 필드 | ... |
| S-01.excluded | 쓰지 않는 부분과 이유 | ... |
| S-01.version | 판·내려받기 URL | ... |
### 변경 이력

## 한국어 뜻풀이 방식(4절 결정)
## 앱 내 고지 문구(5절)
```

- 표의 한 행에는 사실 하나만 적는다. 워크플로가 행 단위로 주장을 뽑아 원 출처와 대조한다.
- 근거 칸에는 URL과 함께 원 출처의 문장을 짧게 인용한다. 열지 못한 페이지는 "열지 못함(이유)"으로 적고 상태를 `미확정`으로 둔다.

### `docs/content/manifest.json`

파이프라인과 저작자 표시 화면이 읽는 기계용 목록이다. `sources.md`와 `id`·라이선스가 같아야 한다.

```json
[
  {
    "id": "S-01",
    "name": "JMdict",
    "homepage": "https://…",
    "downloadUrl": "https://…",
    "version": "YYYY-MM-DD",
    "sha256": "내려받은 파일의 체크섬(파이프라인 첫 실행 때 채움)",
    "license": "CC BY-SA 4.0",
    "licenseUrl": "https://creativecommons.org/licenses/by-sa/4.0/",
    "attribution": "앱 화면에 보일 저작자 표시 문구",
    "shareAlike": true,
    "modifications": "앱에서 가한 변형(급수 필터, 한국어 번역 추가 등)",
    "usedFields": ["…"],
    "excluded": ["…"],
    "status": "confirmed | unconfirmed | excluded",
    "checkedAt": "YYYY-MM-DD"
  }
]
```

- `status`가 `confirmed`가 아닌 자료는 파이프라인이 내려받지 않는다.
- `id`는 바꾸지 않는다. 콘텐츠 DB 행의 출처 열이 이 값을 가리킨다.

## 4. 한국어 뜻풀이

JMdict에는 한국어 뜻이 거의 없다. **2026-11-01 사용자 결정(`docs/content/decisions.md` D-02):** 방식 A(JMdict 영어 뜻을 참고·번역)를 허용하고, 번역 결과는 JMdict의 파생물로 취급해 콘텐츠 DB와 함께 CC BY-SA로 배포하며 출처와 변경 사실을 표기한다. B는 병용할 수 있고, C는 자료가 확인되면 따로 검토한다. 검수 수준(전수/표본, 검수자)은 D-03에서 사용자가 정한다(미정).

| 방식 | 출처 표기 | 주의 |
|------|-----------|------|
| A. JMdict 영어 뜻 → 기계 번역(LLM 등) → 검수 | "JMdict 영어 뜻을 바탕으로 번역"과 원 자료 라이선스 | 파생물로 취급해 원 자료의 동일조건변경허락 의무를 따른다(D-02). 생성 도구·날짜를 남긴다 |
| B. 직접 집필(jlpt-content-author) | 프로젝트 자체 작성 | 작성자가 다른 사전의 한국어 뜻풀이를 옮기지 않는다 |
| C. 라이선스가 확인된 일한 대역 자료 | 해당 자료의 표기 | 2절 확인 항목을 그대로 거친다 |

어느 방식이든 행마다 다음을 남긴다(열 이름은 `architecture.md`에서 정한다):

- 뜻 출처: `jmdict-translated` / `authored` / 자료 ID
- 생성 방법: 예 `llm:<모델>@<날짜>`, `human`
- 검수 상태: `unreviewed` / `sampled`(표본 검수 묶음에 포함) / `reviewed`, 검수 날짜

검수되지 않은 뜻을 검수된 것처럼 보이게 하지 않는다. 화면에서 검수 상태를 어떻게 알릴지는 ui-designer가 정한다.

## 5. 앱 내 저작자 표시

- 저작자 표시 화면은 매니페스트에서 생성된 데이터로 그린다(`compose-app-dev` 9절). 앱이 쓰는 모든 `confirmed` 자료에 대해 자료 이름, 저작자 표시 문구, 라이선스 이름과 링크, 앱이 가한 변형을 보여 준다.
- 함께 둘 고지: "JLPT 급수 분류는 공식 자료가 아니라 커뮤니티 목록에 근거한다", 한국어 뜻 생성 방식(4절), 청해 음성을 만드는 방식(D-04 결정에 따름), 직접 작성한 문제·설명은 실제 시험 문항이 아니라는 안내.
- **콘텐츠 DB 배포 조건(2026-11-01 사용자 결정, `docs/content/decisions.md` D-01):** JMdict·KANJIDIC2 기반 데이터와 파생 한국어 뜻을 포함한 콘텐츠 DB는 원 자료와 호환되는 버전의 CC BY-SA로 배포한다. 앱 코드는 DB 파일과 분리해 별도 라이선스로 둔다(D-05, 미정). `sources.md`에는 적용할 CC BY-SA 버전과 자료별(KanjiVG, Tatoeba 등) 호환 근거를 라이선스 전문 인용과 함께 행으로 적는다.

## 6. 검증과의 연결

`jlpt-app-orchestrator`의 `license-verify` 워크플로가 `sources.md`의 표에서 주장을 행 단위로 뽑고, 주장마다 검증자 두 명(원 출처 문장 대조, 라이선스 전문과 의무 대조)이 반박을 시도한다. 두 명 모두 확인해야 `확정`이다. 표에 없는 내용은 검증되지 않으므로 확정될 수 없다.
