# JLPT 학습 앱 — 제품 계획

작성: 2026-11-02 · 상태: 개발 준비 단계(하네스·빌드 골격만 있음)

이 문서는 무엇을 어떤 순서로 만들지 정한다. 구체 설계(모듈 계약, 스키마, 마일스톤 완료 조건)는 개발 2단계에서 `docs/spec/architecture.md`와 `docs/spec/milestones.json`에, 출처·라이선스는 1단계에서 `docs/content/sources.md`에 기록된다.

## 1. 목표와 사용자

- 한국어 화자가 일본어능력시험(JLPT) N5~N1을 준비하는 Android 앱. UI·설명·뜻풀이는 한국어.
- 하루 몇 분씩 꾸준히 쓰는 앱: 간격 반복으로 단어·한자를 오래 기억하게 하고, 문법·문제·청해로 시험 형식에 익숙해지게 한다.
- 오프라인 우선: 콘텐츠는 앱에 번들된 DB, 학습 기록은 기기 안 Room. 인터넷 권한을 쓰지 않는다.

## 2. 기능(우선순위 순)

| 순위 | 기능 | 핵심 |
|------|------|------|
| 1 | 단어·한자 플래시카드 + 간격 반복(SRS) | 스케줄러는 순수 Kotlin 모듈(`:core:srs`)로 분리하고 테스트 우선. FSRS 계열 또는 SM-2 계열 중 설계 단계에서 근거를 들어 선택 |
| 2 | 문법 학습과 예문 | 직접 작성한 한국어 설명, 예문(직접 작성 또는 허용 라이선스 자료) |
| 3 | 급수별 모의고사·문제 풀이 | 직접 출제한 문항만, 원점수 표시(척도 점수 흉내 없음) |
| 4 | 청해(듣기) 연습 | 직접 쓴 대본을 기기 TTS(ja-JP)로 재생. 녹음 자료 없음 |

**MVP = 1순위 전체 + 급수 선택 + 저작자 표시 화면 + 오프라인 동작.** 2~4순위는 MVP 뒤에 차례로 더한다.

## 3. 마일스톤 계획(초안)

아래는 묶음 단위 계획이다. 2단계 설계에서 android-architect가 이를 완료 조건이 있는 마일스톤(`milestones.json`)으로 나눈다.

| 묶음 | 내용 | 담당(예상) |
|------|------|------------|
| 준비(완료) | 하네스, Gradle 골격(`:app`, `:core:srs`, `:core:quiz`), 빌드·테스트 확인 | — |
| A. 콘텐츠 근거 | 후보 자료의 출처·라이선스를 원 출처로 확인(1단계 워크플로), 한국어 뜻풀이 방식 결정 | content-licensing-analyst |
| B. 설계 | 아키텍처(SRS 선택, DB 두 개, 안정 ID), UI 디자인, ECC 설계 검증, 사용자 승인 | android-architect, ui-designer |
| MVP-1 | SRS 스케줄러(테스트 우선) | feature-engineer(opus) |
| MVP-2 | 콘텐츠 파이프라인 v1: 어휘·한자 + 급수 매핑 + 한국어 뜻 + 저작자 표시 데이터 | content-engineer |
| MVP-3 | 한국어 뜻 검수(우선 N5·N4) | jlpt-content-author |
| MVP-4 | 앱 골격: 테마·일본어 글꼴 로캘, 내비게이션, 콘텐츠 DB·학습 기록 DB | feature-engineer |
| MVP-5 | 오늘의 복습·플래시카드 화면, 급수 선택·새 카드 한도 설정 | feature-engineer |
| MVP-6 | 단어·한자 목록·상세(후리가나, 필순은 KanjiVG 확정 시) | feature-engineer |
| MVP-7 | 저작자 표시·고지 화면, 실기기 확인 | feature-engineer, 메인 |
| 2순위 | 문법 콘텐츠(N5부터) → 문법 화면 → 문법 카드 SRS 연동 | author, content-engineer, feature-engineer |
| 3순위 | `:core:quiz` 채점 → 문항 작성(N5부터) → 문제 풀이·모의고사·결과 화면 | feature-engineer, author |
| 4순위 | TTS 인터페이스 → 청해 대본 작성 → 청해 화면 → 실기기 TTS 확인 | feature-engineer, author |

급수 확장은 콘텐츠 마일스톤 단위로 한다(N5 → N4 → … → N1). 앱 코드는 처음부터 다섯 급수를 모두 다룬다.

## 4. 콘텐츠·라이선스 원칙

- JLPT 공식 어휘·문법 목록은 없다. 급수 태그는 커뮤니티 목록에 근거하며 앱에 "공식 아님"을 밝힌다.
- 기출 문제·시판 교재 문장을 복제하지 않는다. 모의고사·문법 설명·예문은 직접 작성하거나 허용 라이선스 자료만 쓴다.
- 청해 음성은 녹음 자료를 가져오지 않고 기기 TTS(ja-JP) 또는 라이선스가 확인된 음성만 쓴다.
- 콘텐츠는 재현 가능한 파이프라인(`content/pipeline/`)으로만 만들고, 모든 행이 출처 ID를 갖는다. 출처·라이선스 매니페스트(`docs/content/manifest.json`)에서 앱 내 저작자 표시 화면 데이터를 만든다.

후보 자료(라이선스는 **미확인**, 1단계에서 원 출처로 확인):

| 자료 | 용도 | 알려진 라이선스 |
|------|------|-----------------|
| JMdict (EDRDG) | 어휘(표기, 읽기, 영어 뜻) | CC BY-SA 4.0 |
| KANJIDIC2 (EDRDG) | 한자(음훈, 획수, 한국어 음) | CC BY-SA 4.0 |
| KanjiVG | 한자 필순 | CC BY-SA 3.0 |
| Tatoeba | 예문 | CC BY 2.0 FR(문장), 음성은 쓰지 않음 |
| 커뮤니티 JLPT 급수 목록 | 급수 태그 | 출처·라이선스 확인 필수 |

한국어 뜻은 JMdict에 거의 없으므로 생성·검수 방식과 출처 표기를 1단계에서 제안받아 사용자가 정한다(`content-licensing` 스킬 4절).

## 5. 설계 단계에서 정할 것

| 결정 | 선택지 | 정하는 곳 |
|------|--------|-----------|
| SRS 알고리즘 | FSRS 계열 / SM-2 계열 | architect, 근거와 함께 → 사용자 승인 |
| 한국어 뜻풀이 | **결정(2026-11-01):** JMdict 영어 뜻 참고·번역 허용, 파생물로 표기(`docs/content/decisions.md` D-02). 검수 수준은 미정(D-03) | 사용자 |
| 급수 목록 | 라이선스가 확인된 목록 중 선택 | analyst → 사용자 승인 |
| 콘텐츠 DB 배포 조건 | **결정(2026-11-01):** CC BY-SA(원 자료와 호환되는 버전)로 공개, 앱 코드는 분리해 별도 라이선스(D-01, D-05) | 사용자 |
| 청해 음성 방식 | 기기 TTS / 사전 생성 음성 / 혼합 — 미정(D-04) | 사용자 |
| 파이프라인 언어 | Python 표준 라이브러리(기본) / Kotlin 도구 모듈 | architect |
| 일본어 글꼴 | 기기 글꼴 + 일본어 로캘 / 글꼴 번들(라이선스 기록 필요) | ui-designer, architect |
| 카드 방향 | 일→한 인식, 한→일 회상, 한자 읽기 등 | ui-designer, architect |

## 6. 범위 밖(지금은 하지 않음)

계정·클라우드 동기화, 온라인 기능, 녹음 음성, 손글씨 인식, 공식 척도 점수 예측, 광고·결제.
